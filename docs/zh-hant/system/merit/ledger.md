## 賬戶結構

| 概念 | 含義 |
| --- | --- |
| **功勳** | 物理社內部使用的賬戶記錄單位，用於記錄繳費、消費、活動、獎勵、退款和項目結算 |
| **總賬戶** | 記錄社團整體資金池變化的賬戶，下分固定資金池與流動資金池 |
| **個人賬戶** | 每位會員名下的功勳記錄賬戶，展示本人餘額與本人相關流水 |
| **固定資金池** | 總賬戶中的公共管理部分，用於公共事務、預墊費用、公共器材、活動基礎保障 |
| **流動資金池** | 總賬戶中的日常使用部分，與會員活動、物資領取、項目結算關係更直接 |
| **項目待結算** | 活動、食品、材料包等項目從收入到成本核銷之間的中間狀態 |
| **獎勵池** | 從活動盈利或固定資金池中劃定、經多簽後可向成員發放的獎勵額度 |

## 總賬恆等式

系統總記錄由三部分構成：

```text title="系統總記錄"
T = F + L + P
```

- `T` —— 系統總記錄
- `F` —— 固定資金池
- `L` —— 流動資金池
- `P` —— 項目待結算

個人賬戶合計對應流動資金池：

```text title="個人賬戶合計"
L = Σ Aᵢ
```

A~i~ 表示第 i 位會員的個人賬戶餘額。

## 首期社費的 30 / 70 拆分

會員繳費進入系統後，按當期規則分配：

```text title="當期分配規則"
固定資金池增加 = x × r
個人賬戶增加   = x × (1 − r)
```

**首期收費的公示比例為：30% 進入固定資金池，70% 進入流動資金池並計入個人賬戶。**

後續比例可根據固定資金池狀態調整，但**調整隻影響未來入賬，不回改歷史記錄**。

## 典型流轉

| 場景 | 進入路徑 | 支出 / 核銷 | 最終歸屬 |
| --- | --- | --- | --- |
| 首期社費 | 按 30% / 70% 分配 | 無立即支出 | 固定資金池 + 個人賬戶 |
| 活動收費 | 進入項目待結算 | 活動成本核銷 | 結餘進入固定資金池 |
| 物資領取 | 個人賬戶支付 | 外部成本核銷 | 差額進入固定資金池 |
| 廣告 / 合作收入 | 進入項目或固定資金池 | 扣除相關成本 | 淨結餘進入固定資金池 |
| 獎勵發放 | 獎池鎖定後發放 | 無需外部支出時不核銷 | 從獎池進入個人賬戶 |
| 退款 / 註銷 | 個人賬戶申請處理 | 真實資金流出並核銷 | 賬戶關閉或凍結 |

## 鑄造與核銷原則

!!! note "一一對應"
    在內部模型中，功勳與真實資金流轉保持**一一對應**：
    每有真實資金進入系統，系統形成相應記錄；真實資金被外部消費時，對應記錄被核銷。

    這個原則用於防止系統記錄與真實資金脫節。

## 獎勵池規則

正式版把獎勵機制約束為三個核心點：

1. **上限**：非戰時情況下，獎勵池上限**暫時限制為小於對應活動盈利金額**；
2. **自定義**：每次活動的獎池數額可由管理員按活動規格自定義；
3. **多簽**：每次開放獎池，需要 **3 名以上管理員完成 grant 多簽**後才可發放。

獎勵發放完成後，系統記錄獎池減少與個人賬戶增加。
對普通會員而言，其表現形式是賬戶收到一筆獎勵；
對管理層而言，其本質是固定資金池中已鎖定的獎勵額度向個人賬戶轉移。

## 資金流的閉合原則

無論是社費、活動、夥食、廣告、材料包還是獎勵，
最終都需要能解釋清楚：**資金從哪裡來、到哪裡去、哪些進入個人賬戶、
哪些進入固定資金池、哪些因實際支出被核銷。**
