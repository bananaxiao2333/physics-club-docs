## 账户结构

| 概念 | 含义 |
| --- | --- |
| **功勋** | 物理社内部使用的账户记录单位，用于记录缴费、消费、活动、奖励、退款和项目结算 |
| **总账户** | 记录社团整体资金池变化的账户，下分固定资金池与流动资金池 |
| **个人账户** | 每位会员名下的功勋记录账户，展示本人余额与本人相关流水 |
| **固定资金池** | 总账户中的公共管理部分，用于公共事务、预垫费用、公共器材、活动基础保障 |
| **流动资金池** | 总账户中的日常使用部分，与会员活动、物资领取、项目结算关系更直接 |
| **项目待结算** | 活动、食品、材料包等项目从收入到成本核销之间的中间状态 |
| **奖励池** | 从活动盈利或固定资金池中划定、经多签后可向成员发放的奖励额度 |

## 总账恒等式

系统总记录由三部分构成：

```text
T = F + L + P
```

- `T` —— 系统总记录
- `F` —— 固定资金池
- `L` —— 流动资金池
- `P` —— 项目待结算

个人账户合计对应流动资金池：

```text
L = Σ Aᵢ
```

`Aᵢ` 表示第 i 位会员的个人账户余额。

## 首期社费的 30 / 70 拆分

会员缴费进入系统后，按当期规则分配：

```text
固定资金池增加 = x × r
个人账户增加   = x × (1 − r)
```

**首期收费的公示比例为：30% 进入固定资金池，70% 进入流动资金池并计入个人账户。**

后续比例可根据固定资金池状态调整，但**调整只影响未来入账，不回改历史记录**。

## 典型流转

| 场景 | 进入路径 | 支出 / 核销 | 最终归属 |
| --- | --- | --- | --- |
| 首期社费 | 按 30% / 70% 分配 | 无立即支出 | 固定资金池 + 个人账户 |
| 活动收费 | 进入项目待结算 | 活动成本核销 | 结余进入固定资金池 |
| 物资领取 | 个人账户支付 | 外部成本核销 | 差额进入固定资金池 |
| 广告 / 合作收入 | 进入项目或固定资金池 | 扣除相关成本 | 净结余进入固定资金池 |
| 奖励发放 | 奖池锁定后发放 | 无需外部支出时不核销 | 从奖池进入个人账户 |
| 退款 / 注销 | 个人账户申请处理 | 真实资金流出并核销 | 账户关闭或冻结 |

## 铸造与核销原则

!!! note "一一对应"
    在内部模型中，功勋与真实资金流转保持**一一对应**：
    每有真实资金进入系统，系统形成相应记录；真实资金被外部消费时，对应记录被核销。

    这个原则用于防止系统记录与真实资金脱节。

## 奖励池规则

正式版把奖励机制约束为三个核心点：

1. **上限**：非战时情况下，奖励池上限**暂时限制为小于对应活动盈利金额**；
2. **自定义**：每次活动的奖池数额可由管理员按活动规格自定义；
3. **多签**：每次开放奖池，需要 **3 名以上管理员完成 grant 多签**后才可发放。

奖励发放完成后，系统记录奖池减少与个人账户增加。
对普通会员而言，其表现形式是账户收到一笔奖励；
对管理层而言，其本质是固定资金池中已锁定的奖励额度向个人账户转移。

## 资金流的闭合原则

无论是社费、活动、伙食、广告、材料包还是奖励，
最终都需要能解释清楚：**资金从哪里来、到哪里去、哪些进入个人账户、
哪些进入固定资金池、哪些因实际支出被核销。**
